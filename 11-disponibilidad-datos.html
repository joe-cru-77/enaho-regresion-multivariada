Disponibilidad de datos (Data availability)

NotaDisponibilidad de datos

Los microdatos originales provienen de la Encuesta Nacional de Hogares (ENAHO) 2014–2025 del Instituto Nacional de Estadística e Informática (INEI), módulos 200, 300 y 500, disponibles públicamente en el portal de microdatos del INEI (https://proyectos.inei.gob.pe/microdatos/).

La base procesada utilizada en el análisis (base_modelo.csv.gz: 288 241 asalariados, 2 variables objetivo y 19 predictoras) y su diccionario de variables están disponibles en Zenodo: doi.org/10.5281/zenodo.24377138. La base de selección utilizada en el modelo bietápico de Heckman (base_seleccion.csv.gz: personas de 14 años a más, asalariadas o no) se publica en la versión 2 del mismo registro.

El código del pipeline (integración, limpieza, modelado, validación y MLOps) está disponible en GitHub: github.com/joe-cru-77/enaho-regresion-multivariada, archivado en Zenodo con el DOI doi.org/10.5281/zenodo.24377368.

Verificaciones automáticas del pipeline

Antes de publicar se ejecuta source("R/verificar_pipeline.R"). El script comprueba los datos y los resultados que guardaron las páginas 01 a 08 y se detiene si alguna verificación falla. También guarda la huella SHA-256 de cada archivo de datos: quien descargue los datos de Zenodo y obtenga la misma huella tiene exactamente los mismos archivos.

Código 
library(readr)
library(dplyr)

verif <- read_csv(here::here("outputs", "tablas", "verificaciones.csv"),
                  show_col_types = FALSE)

verif |>
  mutate(Resultado = if_else(cumple, "✔ Cumple", "✘ Falla")) |>
  select(Etapa = etapa, `Verificación` = verificacion,
         Obtenido = obtenido, Esperado = esperado, Resultado) |>
  knitr::kable()
Código 
verif |> count(etapa, name = "verificaciones") |>
  mutate(cumplen = tapply(verif$cumple, verif$etapa, sum)[etapa])

¿Qué va en cada plataforma?

Plataforma Qué se publica Para qué
GitHub Solo el código: .qmd, R/, _quarto.yml, renv.lock, README Control de versiones del código y publicación del sitio web (GitHub Pages)
Zenodo (primera opción) Los datos: base_modelo.csv.gz y diccionario_base_modelo.csv Asignar un DOI permanente para citar los datos en el artículo
Mendeley Data (segunda opción) Los mismos datos También asigna DOI
Dataverse (repositorio institucional) Los mismos datos Iniciativa de código abierto que usan varias universidades para alojar datos de investigación

Los datos no se suben a GitHub. Los archivos grandes no se manejan bien en Git, y GitHub no asigna un DOI a los datos.

Pasos para publicar los datos en Zenodo

  1. Crear una cuenta en https://zenodo.org (se puede entrar con la cuenta de GitHub).
  2. New upload → subir:
    • datos/processed/base_modelo.csv.gz
    • datos/processed/diccionario_base_modelo.csv
  3. Completar el formulario:
    • Resource type: Dataset.
    • Title: «Base de modelado ENAHO 2014–2025: ingreso y horas de los asalariados del Perú».
    • Creators: los integrantes del grupo, con su afiliación (Universidad Nacional del Altiplano – Puno).
    • Description: fuente (INEI, ENAHO módulos 200, 300 y 500), población (asalariados ocupados), número de filas y variables, y enlace al repositorio de GitHub.
    • License: Creative Commons Attribution 4.0 (CC BY 4.0).
    • Related works: el enlace al repositorio de GitHub (is supplemented by).
  4. Publish → Zenodo asigna el DOI (10.5281/zenodo.24377138).
  5. Copiar el DOI en esta página, en el README.md, en CITATION.cff y en la sección de disponibilidad de datos del artículo.

Pasos para archivar el código con DOI (GitHub + Zenodo)

  1. En Zenodo: Account → GitHub y activar el repositorio enaho-regresion-multivariada.
  2. En GitHub: crear una Release (por ejemplo, v1.0.0).
  3. Zenodo archiva automáticamente esa versión del código y le asigna su propio DOI.

Cómo citar

Ver el archivo CITATION.cff del repositorio (GitHub muestra el botón Cite this repository).
